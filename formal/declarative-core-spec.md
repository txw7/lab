# Declarative Core Specification

This file freezes the declarative logic target for the current minimal kernel.

Scope:

- fixed configuration `pi0`
- explicit core terms only
- de Bruijn indices only
- monomorphic universes
- hardcoded bootstrap constants `Nat`, `zero`, `succ`, `nat-rec`, `Eq`, `refl`, `eq-rec`
- no general inductives
- no elaboration, tactics, search, or external solvers

The target equation is:

```text
KR(c, pi0) = accept  implies  J(c, pi0)
KL(c, pi0) = accept  is audited by differential agreement with KR
```

where `J` is the declarative typing judgment defined below.

## Core Syntax

Core terms:

```text
t ::= Sort(u)
    | Var(k)
    | Const(c, ())
    | App(t, u)
    | Lam(A, t)
    | Pi(A, B)
    | Let(v, A, t)
```

Contexts:

```text
Gamma ::= [] | A :: Gamma
```

The head of the context is the innermost binder type.

Closure side condition used by the current Lean formalization:

```text
ClosedN(n, t)
```

means every free de Bruijn index in `t` is strictly less than `n`. This is the correct boundary for shift-invariance lemmas; the invalid unrestricted commutation law over open terms is not part of the spec.

## Environment

The global environment contains:

```text
Nat     : Sort 0
zero    : Nat
succ    : Pi(Nat, Nat)
nat-rec : Pi(P : Pi(Nat, Sort u),
             Pi(P zero,
             Pi(Pi(Nat, Pi(P n, P (succ n))),
                Pi(Nat, P n))))

Eq      : Pi(A : Sort u, Pi(A, Pi(A, Sort u)))
refl    : Pi(A : Sort u, Pi(a : A, Eq A a a))
eq-rec  : Pi(A : Sort u,
             Pi(a : A,
             Pi(P : Pi(b : A, Pi(Eq A a b, Sort v)),
             Pi(P a (refl A a),
             Pi(b : A,
             Pi(h : Eq A a b, P b h))))))
```

Plus reducible definitions such as `add`.

## Well-Formed Contexts

Declarative context formation:

```text
WF-EMPTY
---------
|- [] ctx

WF-CONS
|- Gamma ctx
Gamma |- A : Sort u
--------------------
|- A :: Gamma ctx
```

## Context Lookup

Lookup is defined relative to stored binder types:

```text
lookup(A :: Gamma, 0)     = shift(A, 0, 1)
lookup(A :: Gamma, k + 1) = shift(lookup(Gamma, k), 0, 1)
```

Operationally, this matches the current `ctx-lookup` lifting discipline.

## Typing Judgment

Main judgment:

```text
Gamma |- t : T
```

### Sort

```text
SORT
-------------
Gamma |- Sort u : Sort (u + 1)
```

### Variable

```text
VAR
|- Gamma ctx
lookup(Gamma, k) = A
-------------------------
Gamma |- Var k : A
```

### Constant

```text
CONST
env(c) = T
-------------------------
Gamma |- Const(c, ()) : T
```

### Pi Formation

```text
PI
Gamma |- A : Sort u
A :: Gamma |- B : Sort v
--------------------------------
Gamma |- Pi(A, B) : Sort (max u v)
```

### Lambda

```text
LAM
Gamma |- A : Sort u
A :: Gamma |- t : B
------------------------------
Gamma |- Lam(A, t) : Pi(A, B)
```

### Application

```text
APP
Gamma |- f : Pi(A, B)
Gamma |- a : A
--------------------------------
Gamma |- App(f, a) : instantiate(B, a)
```

### Let

```text
LET
Gamma |- A : Sort u
Gamma |- v : A
A :: Gamma |- t : B
--------------------------------
Gamma |- Let(v, A, t) : instantiate(B, v)
```

### Conversion

```text
CONV
Gamma |- t : A
Gamma |- A == B
----------------
Gamma |- t : B
```

## Reduction

One-step reduction relation:

```text
t --> u
```

The current frozen reduction rules are:

### Beta

```text
App(Lam(A, t), a) --> instantiate(t, a)
```

### Zeta

```text
Let(v, A, t) --> instantiate(t, v)
```

### Delta

If `c := v` is reducible in the environment:

```text
Const(c, ()) --> v
```

### Iota for `nat-rec`

Application order:

```text
nat-rec P z s n
```

Rules:

```text
App(App(App(App(Const(nat-rec), P), z), s), zero) --> z

App(App(App(App(Const(nat-rec), P), z), s), App(Const(succ), n))
  --> App(App(s, n), App(App(App(App(Const(nat-rec), P), z), s), n))
```

### Iota for `eq-rec`

Application order:

```text
eq-rec A a P pr b h
```

Rule:

```text
App(App(App(App(App(App(Const(eq-rec), A), a), P), pr), a), App(App(Const(refl), A), a))
  --> pr
```

## Definitional Equality

Definitional equality:

```text
Gamma |- t == u
```

For the frozen current kernel, this is the congruence closure generated by:

- reflexivity
- symmetry
- transitivity
- beta reduction
- zeta reduction
- delta reduction of reducible definitions
- iota reduction for `nat-rec`
- iota reduction for `eq-rec`
- congruence over `App`, `Pi`, and `Lam`

The implementation currently decides this by WHNF plus structural comparison; the proof target is that algorithmic conversion is sound for this declarative relation.

## Certificate Judgment

For a certificate `c` with:

```text
c.context = Gamma
c.term    = t
c.type    = T
```

the intended reading is:

```text
J(c, pi0) := Gamma |- t : T
```

plus side conditions:

- `c.schema_version = 1`
- `c.judgment_kind = :typing`
- `c.config_digest = pi0`
- `c.env_digest = expected environment digest`

Those side conditions are carrier well-formedness, not logical typing rules.

## Deliberate Omissions

Out of scope for this declarative spec:

- universe polymorphism
- cumulativity
- general inductive admissibility
- positivity
- termination checking for user recursion
- eta conversion
- proof irrelevance
- elaboration and metavariables

These are intentionally frozen out so the proof target matches the current executable kernel boundary exactly.
